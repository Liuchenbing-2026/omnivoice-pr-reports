非法采样参数被悄悄转换

https://github.com/vllm-project/vllm-omni/pull/8685
vLLM-Omni · OmniVoice / diffusion TTS未合入 · 固定 main 未解决

触发条件与示例输入

在纯 diffusion 语音服务发送以下请求字段。示例用于解释机制，不代表本次发起了 HTTP 请求。

{"extra_params":{"num_inference_steps":12.5,"guidance_scale":"NaN"}}

根因：哪里绕过了约束

只做 int/float 转换，未检查正整数、布尔值及有限数；数值溢出还可能返回 500。

查看固定 main 源码 ↗

修复前 · 实际行为

请求 → 缺少校验 → 错误结果
12.5 → 12；NaN 进入生成

修复后 · 目标行为

请求 → 生成前检查 → 明确错误
400：拒绝非法数值

具体怎么改

生成前拒绝非正整数步数、布尔参数及非有限 guidance；数值转换溢出走 400 错误路径。

兼容性边界

保留 "12"、12.0、有限的零或负 guidance，以及引擎默认值。

已有验证

历史 CPU 方法级对照：原版 16 失败 / 7 通过 → 修复后 23 通过。

使用真实支持类型、模拟生成；未跑完整 main 模块或整模型。历史本地 mypy 有两项原版已有错误。

请求越多，队列迁移越容易反复扫描

https://github.com/vllm-project/vllm-omni/pull/9028
vLLM-Omni · async chunk · CPU未合入 · 固定 main 未解决

触发：很多请求要等下一块数据

调度器把暂时没有数据的请求从当前队列移入等待队列。原版每移一个都 remove 一次；列表不断被扫描和移动。

修复：一次遍历，批量移除

先收集要迁移的请求；列表统一过滤，队列对象调用 remove_requests。保留原队列对象、剩余顺序和请求状态；没有迁移则不分配过滤结构。

四个请求仅为机制示例；不是实际运行时间线。源码中的逐请求判断与记账仍保留。
