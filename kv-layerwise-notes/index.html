逻辑block不变，物理层按时间复用Logical blocks stay; physical layers reuse storage over time

逐层传输与共享缓冲是两层能力。开启use_layerwise但没有减少共享槽数时，并不自动获得跨层复用。下面的数值仅为等尺寸层的算术示意。Layer-level transfer and shared storage are separate capabilities. 跨层复用的是底层storage。逻辑layer仍存在；同一兼容KV group内的请求block表与物理slot映射需要一致。不同hybrid group不能一概使用同一套block表。Underlying storage is reused across layers. Logical layers remain. Request block tables and slot mappings must agree within a compatible KV group; different hybrid groups must not be assumed to share one universal block table.

9.4%只描述示例中同block数、等尺寸主KV缓冲的比例，不是整卡HBM占用，不包含模型权重、indexer、workspace或额外缓冲，也不是实测容量提升。The 9.4% example concerns equal-sized main-KV buffers at the same block count. It is not total device memory, excludes weights, indexers, workspace and extra buffers, and is not a measured capacity improvement.

两个需要落到固定源码的问题Two questions that need a fixed source revision

容量规划：少分配不等于多容纳Capacity: fewer allocations do not automatically mean more blocks

第二篇文章提出一个版本性问题：upstream先按逻辑层数计算num_blocks，Worker后合并descriptor，节省的HBM未必转成更多逻辑blocks。它没有固定完整源码SHA，本页将此列为待核假设。The second article describes a revision-specific concern: upstream computes num_blocks using logical layers, then the Worker merges descriptors. Saved HBM may not become additional logical blocks. As no complete source SHA is pinned in the article, this remains a hypothesis to verify.

uniform illustration only:
old ≈ available_bytes / (page_bytes × L)
planned ≈ available_bytes / (page_bytes × physical_buffers)

示意公式不能直接复制进多group布局。应先明确page字节是否已经包含K/V、层或组聚合，再计入对齐、保留量、rank最小容量和最终地址范围；Manager、Worker和connector必须使用一致的最终配置。Do not copy the illustrative formula into a multi-group layout. First identify whether page bytes already aggregate K/V, layers or groups; include alignment, reserves, cross-rank capacity and final address bounds. Manager, Worker and connector must use the same final configuration.

保存失败：事件和可见性分开Save failures: events and visibility are separate

第一篇文章描述：put未返回逐key成功状态，发送线程没有即时重试，BlockStored事件可能偏乐观。后续exists发现缺失再补写，属于延迟恢复。该描述仍需对目标提交核实。The first article reports no per-key put result, no immediate sender retry and potentially optimistic BlockStored events. Later exists checks can discover missing keys and trigger a later write; that is delayed recovery. Verify this behavior against the target commit.

ACK丢失也是独立故障：固定官方设计描述的每层完成门没有总体截止时间，发送线程仍活着时可能继续等待。需要单独验证有界等待与安全失败，不能用进程结束替代数据安全。Lost acknowledgements are a separate failure mode: the pinned design describes no overall deadline for the per-layer completion gate, so a live sender can keep waiting. Bounded waiting and safe failure need their own verification; process exit is not proof of data safety.

术语速查Glossary

Prefill / P
预填充：批量处理输入prompt，建立KV。Process the input prompt and build KV.
Decode / D
解码：利用已有KV逐token生成输出。Generate output token by token using prior KV.
HBM
NPU侧高带宽内存；与Host主存分开。Device high-bandwidth memory, distinct from host memory.
H2D / D2H
Host→Device / Device→Host，描述数据方向。Host → Device / Device → Host: data directions.
D2D / D2RH
Device→Device / 本页约定的Device→Remote Host。Device → Device / Device → Remote Host as interpreted here.
TP / TP mismatch
张量并行；两端TP不同，需明确分片映射。Tensor parallelism; unequal TP requires an explicit shard mapping.
block_id / slot
请求逻辑块标识 / 可轮转使用的物理存储槽。Logical request-block ID / reusable physical storage slot.
generation
区分同一slot前后owner的代次，避免旧回执影响新任务。An ownership epoch that keeps stale completions from affecting a new slot owner.
Hybrid KV groups
不同attention或状态布局的多组KV；不等于HBM＋CPU两级。Multiple attention/state cache groups, not merely two-tier HBM + CPU.
