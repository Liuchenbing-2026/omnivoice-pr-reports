03 / INVESTIGATION

完整定位过程：从症状到可检验假设The investigation: from symptoms to a testable hypothesis

  1. 先从最新失败倒查，而非只看日志尾部Work backward from the latest failure, not just the final exception

    提取 10 月 14 日两次失败的阶段打点，找到最早出现的推理 worker 异常。Read the stage markers from two October 14 failures and identify the earliest inference-worker exception.

  2. 将故障链按进程角色拆开Separate the process roles

    trainer 发送权重、rollout 接收权重、vLLM worker 执行推理、HTTP wrapper 处理异常，不把四个栈当一个首因。Separate the training sender, rollout receiver, inference worker, and HTTP error handler rather than assigning one root cause to all four stacks.

  3. 对照客户更新事务的八个阶段Trace the eight-stage update transaction

    abort → 建 rollout worker group → 释放 KV → 建传输组 → 换权重 → finalize → 恢复 KV → 恢复生成。Abort → create the rollout worker group → release KV → build the transfer group → update weights → finalize → restore KV → resume generation.

  4. 核对内存与调度是否同步恢复Check memory residency against scheduling

    客户固定 weights-only wake；vLLM0.23 无条件 resume；Ascend CaMem 按 tag 恢复映射。三处契约拼接后有危险窗口。The customer performs a weights-only wake; vLLM 0.23 resumes unconditionally; Ascend CaMem remaps by tag. Together these create an unsafe interval.

  5. 检查真正的请求入口Inspect the actual request path

    客户 Ray generate 有门禁，但 DevAgent Gateway 直接请求 /v1/completions；原生 HTTP app 没使用该门禁。The Ray generate method is gated, but DevAgent Gateway posts directly to /v1/completions. The native HTTP app does not use that gate.

  6. 运行方法级契约对照Run a method-level contract comparison

    对精确提取的 wake_up 源方法做 8 次 CPU 状态对照：旧版两种 partial-wake 破坏不变量；固定 main 对照保持不变量。Eight CPU state comparisons of the exact extracted wake_up methods: two partial-wake cases violate the invariant in the old revision; the pinned main comparison preserves it.

  7. 核验 PR 实际状态与分支内容Verify PR states and branch contents

    查询 mergedAt / mergeCommit、读取 diff、比较分支祖先并查实际方法；Ascend 68 份 patch / 入口文件未发现对 core wake/pause 的覆盖。Read mergedAt / mergeCommit and diffs, compare ancestry, then inspect actual methods. Sixty-eight Ascend patch/entry files showed no replacement for core wake/pause.

  8. 保留反证与未完成项Preserve counterevidence and open work

    eager 模式仍失败；历史曾多次同步成功；源包与运行现场未完全对应。未做客户 NPU 修正后回归。Eager mode still failed; earlier runs completed many syncs; source/deployment identity is incomplete. No repaired customer NPU rerun has been performed.

这里的 CPU 验证是精确源码方法的隔离状态机检查，使用替代 executor 跟踪内存 tag；它不是真实 vLLM 引擎、HTTP 并发或 NPU kernel 复现。The CPU check isolates the exact source method and uses a substitute executor to track memory tags. It is not a native vLLM-engine, HTTP-concurrency, or NPU-kernel reproduction.

08 / REMEDIATION

分步解决方案：先隔离，再修完整事务Remediation: isolate first, then repair the transaction

A

先隔离 sleep / wake 触发源First isolate the sleep/wake trigger

适用：当前训练与 rollout 分卡，并且 rollout 侧内存允许权重与 KV 常驻。保留其他参数，先做一轮对照。Use this for the current separate-device placement if rollout memory permits resident weights and KV. Keep other settings fixed for the comparison.

actor_rollout_ref.rollout.free_cache_engine=False

建议执行，尚未实跑。该配置让 server 的 release_kv_cache / resume_kv_cache 返回，避免内存释放和 weights-only wake；它不会自动增加 HTTP 门禁。Suggested, not executed. This makes the server’s release_kv_cache / resume_kv_cache return, avoiding release and weights-only wake. It does not automatically add HTTP admission control.

B

把 HTTP 请求纳入更新事务Make HTTP admission part of the update transaction

在 Gateway 或每个 HTTP server 上共享同一更新状态。关闭入口后，先让已经越过入口检查的请求完成 admission，再进行 abort/drain；必须覆盖所有副本。Share update state at Gateway or every HTTP server. After closing admission, settle requests already past the gate before abort/drain, covering every replica.

close HTTP admission
settle in-flight admissions → pause / abort / drain
load weights → post-load / finalize → receive all ACKs
restore KV → invalidate caches → commit version
resume generation → reopen HTTP admission

入口外排队或可重试503都可以，但更新窗口内不能把请求送进引擎。若返回503，网关重试策略必须能识别更新窗口，不能耗尽后把失败占位当作正常回复训练。Queue outside the engine or return retryable 503, but do not submit into the engine during the window. A 503 retry policy must recognize the update interval and must not turn exhausted retries into ordinary training responses.

C

术语速查Terminology

KV cache · 键值缓存KV cache · key/value cache

推理保存的中间状态；内存被释放时不能继续访问。Intermediate inference state that must not be accessed while its memory is released.

partial wake · 部分唤醒Partial wake

按tag只恢复一部分内存；恢复权重不代表缓存也恢复。Restoring only selected memory tags; weights can be resident while cache is not.

scheduler · 调度器Scheduler

决定请求何时执行模型，不等同于HTTP是否接受请求。Decides when a request executes the model, independently of HTTP admission.

H2D · 主机到设备复制H2D · host-to-device copy

报错的位置可能只是异步故障首次被检查的位置。Its stack location may only be where an earlier asynchronous failure becomes visible.

ACK · 完成确认ACK · completion acknowledgement

接收参与方确认本次更新完成；不能只看发送函数返回。A receiver confirms update completion; sender return alone is insufficient.

TP / DP / EP · 并行维度TP / DP / EP · parallel dimensions

分别为张量、数据、专家并行；客户推理DP=1。Tensor, data, and expert parallelism respectively; inference DP is 1 here.
